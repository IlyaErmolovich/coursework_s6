# ЛР №2, часть 2 — оптимизация игрового проекта

Исходные версии изменённых скриптов находятся в этой папке. Контрольные суммы — в `SHA256.txt`. `Assets/GCSandbox` и его Baseline не изменялись.

## Замер до изменений

Пользователь зафиксировал в сетевом матче Host + Client: обычный GC Alloc около 3,3 КБ/кадр, частые всплески около 7 КБ/кадр, выбранный всплеск 34,1 КБ/кадр и CPU Time 15,68 мс. Это показатели отдельных кадров.

В предоставленном захвате `ProfilerCaptures/coursachk3s6_2026-10-08_22-39-04.data` API Profiler показывает для кадра 1909: 34 906 Б суммарно в Main Thread; два узла `NetworkLoop` выделили 29 898 Б и 1 600 Б (697 событий `GC.Alloc`). Для этих событий call stack в захвате отсутствует, поэтому конкретный метод Mirror, KCP или игрового кода не установлен. В том же кадре `CustomNetworkSync.SendSnapshot` выделил 96 Б вне этих узлов.

В 1658 из 2000 кадров `GameMenuUI.Update` выделял по 340 Б. Кадр 1717 содержит отдельный всплеск при `GameObject.Activate` в `GameMenuUI.Update` (17 352 Б), а также выделения TMP при перестроении Canvas. Его следует оценивать отдельно от устойчивых покадровых выделений.

## Изменения

| Скрипт | До | После |
| --- | --- | --- |
| `GameMenuUI.cs` | Два одинаковых присваивания строк денег и слотов каждый кадр; текст цели и подсказки тоже присваивался каждый кадр. | Кэш последнего показанного значения; текст меняется только при изменении; дублирование удалено. |
| `JailDoor.cs` | `Physics.OverlapSphere` создавал массив для диагностического лога, хотя решение использовало только `bounds.Contains`. Подсказка создавалась повторно. | Удалена неиспользуемая диагностическая проверка; возвращаемое условие `bounds.Contains` сохранено. Текст подсказки кэшируется по `holdDuration`; ошибка отсутствующей зоны выводится один раз. |
| `PickupItem.cs` | Интерполированная строка создавалась при каждом наведении. | Кэш по `value` и `itemName`; изменения SyncVar обнаруживаются при следующем обращении. |
| `LootDropZone.cs` | Строки подхода и сдачи денег создавались при каждом наведении. | Кэш по `zoneName` и сумме денег. |

Пример до: `moneyText.text = $"$: {_localInventory.TotalMoney}";` выполнялось два раза в одном `UpdateHUD`.

Пример после: `if (money != _displayedMoney) { moneyText.text = $"$: {money}"; _displayedMoney = money; }`.

Пример до: `Collider[] hits = Physics.OverlapSphere(player.transform.position, 0.1f);` и `return inside;`.

Пример после: `return prisonZone.bounds.Contains(player.transform.position);` — тот же источник ответа без массива и двух диагностических строк.

## Проверка

- Unity MCP: принудительная компиляция завершилась; Console: 0 ошибок.
- `validate_script`: 0 ошибок для четырёх изменённых скриптов.
- Host из `MainMenu` открыл `Lobby`; Console: 0 ошибок и предупреждений.
- `Game.unity` проверена через `manage_scene.validate`: отсутствующих скриптов и сломанных префабов нет.
- Полный матч Host + отдельный Client и замер после изменений не выполнялись автоматически. Показатели GC Alloc/FPS после оптимизации не установлены.

## Проверка после изменений

Запустить `MainMenu` в Host и подключить отдельный Client, назначить команды и начать матч. В одинаковых условиях до и после сравнить CPU Usage → Hierarchy → GC Alloc для `PlayerLoop`, `GameMenuUI.Update`, `NetworkLoop`; проверить простои, передвижение, наведение на предмет, дверь карцера и зону сдачи. Сохранить захват Profiler и сравнить одинаковые интервалы после загрузки сцены. В отдельном Player измерить без накладных расходов Editor. Для определения источника всплеска `NetworkLoop` включить Allocation Call Stacks на коротком захвате и раскрыть `GC.Alloc` до методов Mirror/KCP или игровой сериализации.
